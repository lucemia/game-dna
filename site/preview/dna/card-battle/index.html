Play cards against foes that show what they will do next. A complete starter game you can extend.

What it does

A turn-based card battle: draw a fanned hand each turn, drag a card onto a foe (a target arrow follows; keys and taps work too) and pay its cost from a small energy pool; draw and discard piles reshuffle when the draw runs out.

Made fordeck-building roguelites and run-based card gamesRPG battles where actions are cards drawn from a deckpuzzle-like boss fights where the player reads the foe's next moveboard or tabletop adaptations with an energy budget per turnshort encounters inside an adventure or map game (one fight per node)

Tested: 8/8 runs on unseen games passed · visual review 7.8

# Add Card battle with intents to my game

Add the game element below to MY existing game, which you have not seen. It is a finished module file given with this prompt:

- `card-battle.js` (one global, `GameDNA_CardBattle`), API reference `card-battle.README.md`

README example names are placeholders.

## Shared premises

1. **Include each module file verbatim; never edit it.** Load it with its own `<script src>` before the game's script, or paste it unchanged into its own `<script>` tag. If a module seems to need a change, adapt my game around it and tell me.
2. **Resolution:** keep my game's native resolution and integer scaling as they are. Call module draw functions on my 2D context inside the same transform as my sprites (one module pixel = one game pixel), and keep my game's own image-smoothing setting (off for pixel art, on for smooth or HD games; never switch it).
3. **Time:** drive every module from one fixed 60 Hz step (1000 / 60 ms). If my loop uses variable delta time, accumulate it and run whole steps (at most 250 ms per frame). Turn/phase logic stays mine; modules still update every step to animate.
4. **Coordinates:** native screen pixels (world minus camera) unless a section says tiles.
5. **Art and names:** anything new you draw or name is original (no real game, character, place or brand names); English UI text; do not restyle my game.
6. **Hook, don't replace:** add calls or change bodies; never delete or rename a function.
